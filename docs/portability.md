# portable-v2 工程迁移

本版在独立工作区改造，原正式训练仍固定在旧服务器版本，不混用结果。
改动涉及路径、依赖安装、资源守护、验收与发布方式；课程定义、网络和损失不变。
portable-v2 在目标机器完成自身验收前，不被视作原正式协议的数值等价复现。

## 版本隔离
- 历史入口：提交 0ecf164，旧正式实验继续使用它。
- 新入口：当前 python.sh，默认使用仓库内 .venv 和 .artifacts。
- 配置：configs/train.yaml 不含用户路径；configs/protocol.json 是新运行的协议模板。
- docs/legacy-v1 是历史证据，路径脱敏，禁止作为新机器的通过凭据。
- 每次本机 GPU 验收生成相对源码哈希、依赖版本、GPU 选择及线程设置组成的锁。
- 运行时路径可变；源码/环境/资源设置变化会被拒绝，需新 CRAFT_RUN。
- 新机器不保证 GPU 位级结果相同，不复制旧模型冒充新的独立训练。

## 验证分层
1. 新个人虚拟环境安装 CPU 依赖并 pip check。
2. 环境日程、边界、恢复、输出路径及锁拒绝篡改测试。
3. 从无旧本机配置的导出副本执行检查。
4. CUDA 机器显式执行 validate_runtime.py --gpu：400步恢复比较、5100步边界、100开发回合。
5. 通过后串行正式矩阵，再统一正式评估。

本次工程修改不启动第二个 GPU 任务。CUDA 安装入口与 GPU 验收流程不等于已在另一块 GPU 上完成复现；
最终实测范围以本次交付说明为准。用户无需旧服务器账号和私钥即可使用 CPU 路径。
