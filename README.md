# CraftScaffold｜从练习到独立生存

> **最新结果（2026-10-13）**：Crafter self-branch scale-v3 的 Branch 与 Source 两臂均已完成 1.5M 动作训练，并完成 100 局自然场景评测。共同 600k baseline Score 为 11.87；Branch 从 1M 的 19.14 到 1.5M 的 23.66，最高测得 24.94（1.3M）；Source 从 17.99 到 17.83，最高 20.22（1.37M）。Branch 1.5M 石镐成功率 56%，Source 40%，但两者铁镐均为 0%。610k 初始化点没有标准化评测，且 600k 至约 823k/827k 的早期权重已不存在，因此图上保留测量空档、不插值。两臂各一个训练种子，结果是有希望的单配对证据，不是跨种子因果结论。
>
> 路线动机、实现差异、失败记录与证据边界见[技术路线迭代与结果](docs/technical-route-iterations.md)；[600k–1.5M 分数曲线](docs/results/scale-v3-600k-to-1500k/score-curve.svg)、[逐节点 CSV](docs/results/scale-v3-600k-to-1500k/scores.csv)和[清理审计](docs/results/scale-v3-600k-to-1500k/cleanup-audit.json)可复核完整数据。RA-HB v2 是已停止的独立失败路线，详见[复盘](docs/ra-hb-v2-postmortem.md)，不能与 self-branch 分数混为一组。

**基于DreamerV3 + Crafter的强化学习课程项目：在带帮助的场景中练习，再检验智能体能否在正常世界里独立生存和制作工具。**

我们研究的工程问题是：**相同训练预算下，什么时候提供帮助，能让最终游戏能力更好？**
复用成熟的世界模型强化学习算法，自行实现辅助出生场景、训练日程、断点恢复与评估审计。
目标是做出可运行、可解释、有对照数据的游戏学习系统，而非宣称新算法或通关全部成就。

截至2026-10-06，原始 **3种方法 × 3个训练种子** 全部完成，每个模型训练300,000步、评估100个自然场景，共900回合。
综合成绩平均上有正向收益，但跨训练种子不稳定，尚未获得稳定的高级制作能力。

## 一眼看懂项目

Crafter是开源二维生存游戏，包含采集、战斗、生存和工具制作等22项成就。
原始3×3实验训练的是完整游戏奖励下的多技能策略，**并非只训练木镐**；木镐是预设的重点观察指标。

![正常出生与辅助出生场景](docs/assets/starts.png)

上图是旧协议同一地图种子下的真实环境画面。旧辅助只在训练时改变出生条件：玩家右侧放置工作台、木头库存设为1。
智能体仍要自己选择动作；没有专家动作标签，没有直接赠送工具、成就、奖励或无敌状态。
这属于**人工设计初始状态课程下的强化学习**，不称为严格无监督学习。

上图来自固定辅助模型seed11的自然场景评估第2回合：正常出生 → 采木 → 放工作台 → 制作木镐 → 采石。

## RL体现在哪里？

~~~text
游戏图像、环境奖励、回合标志
           ↓
经验池 → DreamerV3世界模型 → 模型内想象轨迹
                               ↓
                         actor / critic学习
                               ↓
                         动作返回真实游戏
~~~

我们复用DreamerV3的网络、损失与想象学习机制，当前改动训练环境的初始分布、日程和统一训练奖励过滤；自然评测保留原始奖励。
actor和critic没有额外结构化特权输入；场景帮助通过正常图像可见。
诊断器读取库存与成就用于统计，不能作为策略输入。

## 三种训练安排

每个模型从头训练300,000个保留环境动作，分为120个区块，每区块2,500动作。

| 方法 | 初始场景安排 | 训练中的辅助动作 |
|---|---|---:|
| natural（自然训练） | 全程正常出生 | 0 |
| fixed_mix（固定辅助） | 每4个区块有1个辅助区块 | 75,000 |
| fading_mix（前置后撤除） | 前150k动作一半辅助；后150k全部正常 | 75,000 |

“撤除”是两阶段安排，**不是平滑衰减**。辅助区块内死亡后仍按辅助条件出生。
三组都有相同的区块边界截断和稳定对象排序；截断不作为死亡终局。因此natural是本项目协议内基线，不等同上游论文配置。

训练种子11、23、41代表三次独立随机训练运行，**不是只在三个固定世界训练**；每次运行包含多个随机世界。
最终模型使用共同的100个自然评估场景，采用固定随机数的sampled eval，而非argmax。
所有原始最终权重冻结后才进行该轮评估，没有按这100回合选择原实验checkpoint。

## 历史3×3初步结果

### 综合能力：标准Crafter Score

每项成就的成功率为p（0–100），每个模型的Score为exp(mean(log(1+p)))−1，覆盖全部22项。
先计算各模型分数，再对三个训练种子等权平均；不是把900回合冒充900次独立训练。

| 方法 | seed11 | seed23 | seed41 | 三种子均值 |
|---|---:|---:|---:|---:|
| 自然训练 | 4.528 | 7.805 | 5.379 | **5.904** |
| 固定辅助 | 9.653 | 3.973 | 6.182 | **6.603** |
| 前置后撤除 | 7.859 | 3.635 | 7.755 | **6.416** |

![各独立训练运行的Crafter Score](docs/assets/scores.png)

固定辅助相对自然训练平均增加0.699分（约11.8%），撤除辅助增加0.513分（约8.7%）。
两种辅助在2/3个配对训练种子上优于自然训练，在另一个种子上落后。
因此，**平均综合效果为正，但不能声称稳定优越**；也不能只凭一个失败种子否定整体收益。

### 同时保留未改善的指标

木镐是原协议预设主要指标，22项综合分析用于补充全局评价，不能用它事后替换原指标来宣称原假设已证实。

| 指标（三种子均值） | 自然训练 | 固定辅助 | 前置后撤除 |
|---|---:|---:|---:|
| 木镐制作成功率 | 40.33% | 39.00% | 29.33% |
| 采石成功率 | 11.67% | 19.67% | 13.67% |
| 每回合不同成就数 | 6.30 | 6.22 | 6.53 |
| 每回合原始回报 | 5.38 | 5.31 | 5.62 |

木镐成功率的三次独立结果分别为：自然32/41/48%，固定65/1/51%，撤除42/0/46%。
综合Score、单项成功率、成就数与回报衡量不同侧面，不能互相替代。
铁与钻石采集、铁工具等仍未成功；撤除组平均Score略低于固定组，但不能将完整日程差异单独归因为“遗忘”或“依赖”。

**该阶段结论**：人工辅助值得继续作为工程候选，收益主要体现为部分技能覆盖和综合Score的改善；一致性与高级技能仍是短板。
三个种子仅提供课程级初步证据，不支持SOTA、统计显著性或算法首创声明。

可在安装后运行 ./python.sh tools/verify_results.py，无需模型或GPU，重新计算全部九份成绩。

可复核数据：[九模型指标与检查点哈希](docs/results/formal-300k.json) · [900回合成就与回报](docs/results/episodes-300k.json) · [全部22项成功率CSV](docs/results/achievements-300k.csv)。
九次训练共保留270万动作，实际完成2,715,928动作，其中恢复重复15,928动作；训练尝试累计约50.63小时，不含全部开发与修复成本。
后期部分运行使用traceguard-v1移除未启用追踪的多余同步；短程等价检查通过，但不能视为所有长轨迹逐位等价的证明。

当时取消了旧六路续训任务，并从上述原始300k模型中，每种方法选择综合Score最高的一个候选：

## 技术路线怎么筛到 Branch / Source：小批次证据与长训曲线

这部分是项目的核心技术路线记录。所有结果按各自协议报告；30 回合机制筛选、100 回合正式节点、训练中产生的解锁事件不能混成同一种成功率。

### 1. 从 baseline 诊断具体失败点

共同技术起点是自然 DreamerV3 的 **610k 完整检查点**。600k baseline 的标准化独立自然评测为 100 局、Score **11.86897**，它是可比较的基线参照，但不是 610k 初始化模型的实测分数。

我们没有只看“模型不会做高级工具”这一总体现象，而是重放真实自然轨迹，对齐观察、动作、奖励、睡眠状态、背包和附近设施。在一个 10k baseline 片段中：

- 石镐有 **493 步**同时满足清醒、材料和附近设施可用，策略只在其中发出 **1 次**石镐指令；
- 铁镐有 **99 步**可行机会，策略在可行状态下发出 **0 次**铁镐指令；
- 完整环境重放匹配了保存的图像、奖励、终止和新成就事件。

所以优先问题不是“再给一次成功奖励”或“Crafter 配方实现错误”，而是成功机会稀少且策略常在机会出现时没有选择目标动作。此诊断仍不能单独判断 actor、critic、世界模型各自的责任。

### 2. 有界行为探索：增加成功经验，不等于学会复现

从同一 600k checkpoint 做了 control / explore 配对试探。Explore 只在辅助回合开头 32 步以 50% 概率覆盖均匀随机动作；不读取背包、成就、目标标签，也不教正确动作。两组各新增 10k 交互，随后做自然和辅助评测。

Explore 在训练过程产生 **11 次石镐、3 次铁镐新解锁**，control 为 **1 次、0 次**。但最终策略评测中，两组准备石镐和铁镐都为 **0/30**；自然 Score 分别为 Explore **11.061/30**、control **12.230/30**。随机覆盖增加了训练时实际尝试和解锁，却未转化成能独立复现的策略，且该筛选未通过预先设定的晋级门槛。训练期的成功事件不能算最终策略成功。

### 3. Curious Replay 启发试探：有小幅总分信号，没有目标技能信号

下一步保持相同来源、随机探索设置和 10k 训练预算，只改变回放选择和逐步世界模型损失反馈。CR-inspired 候选在 30 局自然评测得 **12.744**，均匀回放 control 得 **12.230**；但准备石镐、铁镐仍均为 **0/30**，所以没有晋级到长训。CR 臂训练中出现石镐和铁镐新解锁，不代表策略自主成功。回放账本确认反馈实际发生，但成功结果没有稳定地比同年龄段其他样本获得更高采样次数。

实施前还有独立的工程小测：选择器 6 项 CPU 测试、回放集成 5 项、逐步损失 hook 4 项；真实 600k checkpoint 的 GPU 连续／恢复预检用 16 个环境动作、128 次回放抽样并核对 3,555 个逐步模型损失值。它们验证的是接口、数值和恢复一致性，不是学习收益。CR 原论文使用的组件、参数和优先级聚合不完全等同于本地适配，本试验明确称为 **CR-inspired**，不是完整复现。

证据与实现边界见 [CR 接入评估](docs/cr-integration-assessment.md)、[探索试探记录](docs/ironpick-research-roadmap.md)、[CR 轨迹重建](docs/results/cr-exploration-recipe-replay.json)。

### 4. 为什么保留 Branch 和 Source 两臂

短程试验说明“制造更多成功经验”与“模型能从成功经验学会何时制作”是两个问题。scale-v1/v2 因此保留一个匹配的 Source 轨迹对照，再问一个更窄的问题：**在相同起点、回放机制和预算下，覆盖不同成功分支的轨迹，是否比重放匹配数量的源策略成功轨迹更有用？**

两臂都从同一个 610k 完整 Dreamer/Curious-Replay checkpoint 恢复；共有训练 seed、配置和自然环境预算，CR 回放开启，辅助场景权重为零，随机动作覆盖关闭。两臂的差异是成功轨迹 bank：

- **Branch bank**保留从冻结策略分支构造中产生的、经 Crafter 原生环境验证的完整成功轨迹；两个地图命名空间合计 26 个完整序列、5,881 个转移。
- **Source bank**使用同一冻结源策略的成功轨迹，并按 branch 覆盖量匹配重复；合计约 26 个序列、6,000 个转移。它是必要对照，帮助排除“只是多塞了一批成功经验”或回放量不同的解释。

这里的 branch/source 指**训练期回放数据来源**，不是两种网络结构，也不是分别从不同 baseline 起跑。Branch 轨迹的构造动作/分支行为不作为专家监督标签；学生部署和独立评测时不接收轨迹来源、目标技能或环境真值。两个协议、bank 文件哈希与构造审计见 [Branch protocol](scripts/scale-v3/student-branch-protocol.json)、[Source protocol](scripts/scale-v3/student-source-protocol.json)。

### 6. 从共同起点到 1.5M：曲线读法和能力变化

下表中的 600k 是共享自然 baseline 参考点；两臂**实际从 610k 同一完整 checkpoint 起跑**。610k 没有同协议标准化评测，因此不要把 600k 点说成初始化点的精确成绩。之后每个已报告节点都是 100 局自然评测：

| 节点 | Branch Score | Source Score | Branch 石镐 | Source 石镐 | Branch 铁矿 | Source 铁矿 | 铁镐（两臂） |
|---|---:|---:|---:|---:|---:|---:|---:|
| 600k 共同 baseline 参考 | 11.87 | 11.87 | 0% | 0% | 0% | 0% | 0% |
| 1M | 19.14 | 17.99 | 34% | 28% | 1% | 4% | 0% |
| 1.5M | 23.66 | 17.83 | 56% | 40% | 10% | 1% | 0% |
| 各臂最佳已测节点 | **24.94**（1.3M） | **20.22**（1.37M） | 逐点见 CSV | 逐点见 CSV | 逐点见 CSV | 逐点见 CSV | 0% |

从 1M 到 1.5M，Branch Score 增加约 **4.52**，Source 约 **-0.16**。Branch 1.5M 比 Source 高 **5.83 Score**，自然石镐成功率高 **16 个百分点**；但分数在最佳节点后会回落，所以“训练更多一定更好”不成立。最终两臂铁镐和钻石成功率仍为 **0/100**，不能把石镐的改善表述成铁镐链已打通。

数据覆盖并非无缝：600k 到第一批幸存评测节点（Branch 822,987、Source 826,855）之间的旧权重已经删除；该区间无曲线点，不做插值。后续 1.01M–1.5M 每臂 50 个节点均有独立 100 局评测，pre-1M 幸存节点中 31 个已补测。完整曲线、22 项成就、step/agent SHA 和评测输出路径在 [scores.csv](docs/results/scale-v3-600k-to-1500k/scores.csv)；图见 [score-curve.svg](docs/results/scale-v3-600k-to-1500k/score-curve.svg)，清理审计见 [cleanup-audit.json](docs/results/scale-v3-600k-to-1500k/cleanup-audit.json)。

### 7. 当前能下的结论与不能下的结论

**支持的结论**：多分支成功轨迹 bank 在当前单种子配对扩展中表现最好；它在两命名空间的 750k screen/actor 测试和 1.5M 自然终点评测都优于 Source，长训后石镐和综合 Score 的信号仍在。相较单纯随机探索、仅加状态预测辅助损失，这条数据回放路线更值得优先做多种子复验。

**仍不能声称**：self-branch 已经统计显著优于其他算法；训练能稳定学会铁镐；结果可迁移到所有地图或其他环境；Branch bank 单独造成了全部差异；推理期视觉筛选等同于策略内生能力。

最直接的下一步是冻结同一 610k 源状态、相同训练预算和自然评测协议，至少做多个配对训练种子，比较均匀回放、匹配 Source bank 与 Branch bank；把自然 Score 设为综合主指标，石镐为重点技能指标，铁镐为后续链条指标。继续记录可行机会中的目标动作率和每千步无效/重复制作，避免只靠端点 Score 解释机制。
## 快速开始（Linux / Python 3.11）

Windows 请使用 WSL2 Linux 环境；不支持原生 Windows 训练。
将仓库克隆到**自己的可写目录**，不需要原作者服务器、SSH key、固定 GPU UUID 或外部模型目录。

```bash
git clone https://github.com/TwilightGlimmer/craft-scaffold.git
cd craft-scaffold
bash setup.sh cpu
./python.sh tools/doctor.py
./python.sh tools/validate_runtime.py
```

CPU 路径用于安装、配置和环境测试，不开展正式训练。安装只写仓库内的 `.venv` 与 `.artifacts`，不修改系统 Python。
默认需要 `python3.11`，可通过 `CRAFT_BOOTSTRAP_PYTHON` 指定个人 Python 3.11。
首次安装需要网络。依赖分为 [CPU](requirements/cpu.txt) 和 [CUDA](requirements/cuda.txt)；CPU 依赖闭包已固定在 constraints.txt；CUDA 额外驱动运行库由安装器解析，运行时记录全部实际版本。

### GPU 配置与目标机器验收

在有可用 NVIDIA GPU、兼容 CUDA 12 JAX 驱动的 Linux 机器上：

```bash
bash setup.sh cuda
cp .env.example .env.local
# 编辑 .env.local，选择个人存储目录和空闲 GPU
./python.sh tools/validate_runtime.py --gpu
./python.sh scripts/curriculum_formal_worker.py
```

GPU 验收是明确的耗时操作：检查设备、400 步连续/两次恢复一致性、5,100 步课程边界预检、100 回合开发评估。
验收通过后才生成当前机器的 `local-validation.json`，正式调度器拒绝借用历史验收解锁训练。
若验收中断，换一个新的 `CRAFT_RUN` 重新验收，避免把旧产物误认为新测试结果。
不要在另一训练管理程序仍占用目标 GPU 时启动。

**可配置项**（可写进被 Git 忽略的 `.env.local`，这是可信 Bash 配置）：

| 变量 | 默认值 | 用途 |
|---|---|---|
| CRAFT_DATA_ROOT | 仓库/.artifacts | 模型、报告、日志和缓存根目录 |
| CRAFT_RUN | portable-v2 | 实验版本名，只允许字母、数字、下划线和连字符 |
| CRAFT_GPU | 0 | 单个 GPU 编号或 UUID |
| CRAFT_THREADS | 2 | CPU 线程和亲和性上限 |
| CRAFT_PYTHON | 仓库/.venv/bin/python | 可选个人 Python 环境 |

所有命令统一经过 `./python.sh`。源码、配置、依赖或资源设置改变时使用新实验版本，不能覆盖旧源码锁。
默认单任务、20 GiB 显存和16 GiB进程树内存上限；管理程序检测停滞后从完整检查点分段恢复。
断开终端会影响前台管理程序；长训练请使用自己的 tmux 等会话管理方式。

## 输出、恢复与审计

输出在 `CRAFT_DATA_ROOT` 下按版本隔离：

```text
models/<run>/<method>-seed<seed>/    # 权重、replay、环境/随机数状态、真实交互账本
reports/<run>/                     # 本机验收、源码锁、状态、逐回合评估
logs/<run>/                        # 训练、评估和恢复日志
cache/  tmp/                       # 安装与运行缓存
```

正式矩阵入口串行训练三个方法与三个种子，按 10k 保留动作分段，保存模型、优化器、环境、policy carry、采样器与待处理更新。
管理程序只恢复完整检查点，超过资源上限或连续五次无进展会失败退出，保留诊断信息。
正式评估与开发评估使用不同随机数命名空间，不按正式测试成绩选 checkpoint。

仅加载可信来源的 pickle 检查点。跨依赖版本、跨硬件的逐位一致性没有保证。
